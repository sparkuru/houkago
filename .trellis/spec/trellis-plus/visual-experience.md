# Houkago 视觉与体验契约

## 适用范围与品质要求

用户于 2026-10-05 明确要求将以下约束及项目适配写入共享 spec：

> 以 Awwwards、 Webby Awards、 FWA 获奖级网站为品质标准，完成后从排版、留白、视觉层级、色彩、动效、微交互、响应式和 原创性上自检并持续优化，直到没有明显可提升之处。

本契约适用于后续用户可见页面、组件、文案、主题、动效和交互的规划、实现与检查。
这些奖项是品质参照；不得据此宣称项目已获奖、符合官方评分或获得认证。
实施标准是完整、精致、原创且可用的共同观看体验。八个维度都必须检查，
功能正确、可访问性和响应式可用性也是完成条件。

本文件是视觉方向与心智模型的共享来源。布局与业务细节分别由
[room-runtime](../houkago-kyoushitsu-react/frontend/room-runtime.md)、
[media-provider-danmaku](../houkago-kyoushitsu-react/frontend/media-provider-danmaku.md) 和
[site-configuration](../frontend/site-configuration.md) 定义；使用这些契约，避免另写一套。
后续批准的设计变更要同步更新本契约、相关源码和适用的 implement/check 上下文。
品质要求不扩大当前需求范围，也不自动授权品牌重做、业务变更或新增依赖。

## 固定的视觉方向

沿用已验收的 **Warm Club：放学后的安静社团放映室**。
纸色背景、暖墨正文、木色操作、青绿焦点、建筑式对齐、克制的衬线邀请语，
配合原创教室与投影图形，构成统一识别。首页有邀请感，部室让观看内容成为重心。
新页面应复用这一语言；不要逐页生成无关配色、字体、圆角或装饰风格。

可持续演进的是构图、信息密度、排版细节和反馈质量；保留已批准的身份与行为。
不要为“获奖感”加入背景视频自动播放、装饰性循环动画、滚动劫持、自定义光标、
虚构统计、无意义营销区块，或使常用操作依赖悬停。不得复制获奖网站的构图与素材。
扩展原创图形时，从项目的教室、窗光、座位、投影和楼层语言出发，说明它的用途。
现有 SVG 是视觉资产；未来素材需有来源与使用权记录，不默认引入图库图或远程字体。

## 统一心智模型与信息架构

| 用户认知 | 实现与文案约束 |
| --- | --- |
| 楼层是入口，部室是一次共同观看的空间 | `/` 提供身份与加入/创建入口；`/bushitsu/:id` 进入同一个部室。沿用项目“楼层、教室、部室”词汇及现有字典，不新增并行的频道/会议/直播间概念。 |
| 收到 ID 或 URL 就能找到教室 | 加入是已有邀请用户的主要路径；创建是准备新放映的次要路径。首页不展示其他部室目录，保留隐私说明。 |
| 身份恢复、入室等待、已入室是不同状态 | 恢复、登录、批准等待、拒绝、断连、重连分别给出对应状态与下一步；不得用装饰性 loading 隐藏错误或暗示已获得权限。 |
| 屏幕是观看中心，队列决定放什么 | 播放器优先；队列与统一视频源入口沿用当前 room presentation contract。空播放器保持投影语义及 16:9 舞台，不用多张竞争主卡片挤占屏幕。 |
| 同伴与交流在同一侧栏 | 沿用出席 → 弹幕来源/设置 → 聊天的顺序与共享输入框；“弹幕”和“发送”是两个明确动作，不拆成重复输入或混淆发送目的地。 |
| `+` 是部室辅助操作入口 | 已入室用户从既有菜单访问信息/房主管理、复制链接和返回楼层；等待入室用户使用现有返回链接。不要新增竞争导航入口。 |
| 放映模式与全屏有不同作用 | cinema 保留交流及可达的部室菜单；实际播放器 fullscreen 才按既有契约隐藏外部菜单。不能以放映模式为理由丢失返回路径。 |
| 房主、成员及许可决定能做什么 | 可见状态与操作资格来自当前服务端权限、入室和连接状态；本地选中/动画不能冒充服务端成功。单项删除、排序和清空的权限分工以 room-runtime 为准。 |

公开身份与邀请文字仍由 `config/config.toml` 的既有类型化配置提供，界面词汇由
`houkago-kyoushitsu-core/i18n` 提供。`site.name` 仅作为顶部语义 h1 显示一次，
`entry.hint` 仅在原创教室插画的 figcaption 显示一次；保留最新验收的输入无障碍名称，
不要为填空恢复已删除的重复站名、加入标题、冗余 kicker、首页加入/创建输入的
可见 label 或重复邀请句。
新增说明必须提供新信息；占位文字不能成为输入框唯一的无障碍名称。

## Token 与组件契约

实际值来源是
[`packages/kyoushitsu-core/src/theme/theme.css`](../../../packages/kyoushitsu-core/src/theme/theme.css)。
沿用 `:root[data-theme="warm-club"]` 下的 **primitive → semantic → component** 三层。
React 的主题映射、排版与响应式实现位于
[`src/styles/index.css`](../../../packages/kyoushitsu-react/src/styles/index.css)，
控件复用 [`components/ui`](../../../packages/kyoushitsu-react/src/components/ui)。
不得在组件中复制一组十六进制品牌色或另建 `design-system/MASTER.md`。

| 契约 | 当前基准及扩展方式 |
| --- | --- |
| 色彩 | `--color-canvas` 纸色 `#f6f0e5`；`--color-surface` `#fffdf8`；`--color-text` 暖墨 `#30291f`；`--color-text-muted` `#6d6253`；操作 `--color-accent` 木色 `#8b5b2d`；焦点 `--color-focus-ring` 青绿 `#2f7669`。危险、媒体黑及 provider 色使用其专用语义 token，不占用品牌主操作意义。 |
| 字体 | 复用 `--font-display` 的 CJK 衬线和 `--font-body` 的系统/CJK 正文字体回退链；基准正文 16px、标题 22px、辅助标签 13px。首页邀请语是独立 display 层级；顶部站名保持紧凑 h1。不得以 HTML 标题级别机械决定视觉字号。 |
| 留白 | 复用 `--space-1…8` 的 4/8/12/16/24/32/48/64px；组内间距小于组间间距。首页保持邀请区与入口台的呼吸感，部室采用较密的工作区节奏；大屏不能留下旧布局占位空栏。 |
| 形状与层次 | 复用 8/14/20px 圆角和 card/panel/floating elevation。边框划分信息，阴影说明抬升；次要创建卡片保持安静，不给每个区块同样的强背景和阴影。 |
| 动效 | 常规反馈复用 160/180/220ms 及既有 easing；首页短 reveal 为 8px 位移/淡入，立即可操作。保留菜单现有受 reduced-motion 约束的专属展开节奏；新例外需说明目的，不能扩大成全页弹跳。 |
| 焦点与触控 | 复用 3px 焦点轮廓和 2px offset；按钮、图标操作与输入控件目标至少 44×44px（输入宽度随容器）。focus、hover、active、disabled、pending 的意义在各页面一致。 |

新增可复用语义放在 core theme；应用布局、专属 selector 和断点放在 React CSS。
优先复用既有语义值，缺少明确角色才增加 token。组件局部字号、颜色混合和密度可以
为内容需要调整，但必须派生自这套主题并在设计中说明，不能形成第二套主题。

```css
/* 应用组件使用有角色的 token；主动作与焦点保持不同语义。 */
.watch-invitation-action {
  min-height: var(--control-height);
  min-width: var(--control-height);
  padding-inline: var(--space-4);
  color: var(--color-on-accent);
  background: var(--color-accent);
  border-radius: var(--radius-md);
}
.watch-invitation-action:focus-visible {
  outline: var(--focus-outline-width) solid var(--color-focus-ring);
  outline-offset: var(--focus-outline-offset);
}
```

这是后续实现示例，本次 spec 更新没有新增该组件或改变主题值。
错误做法：同类按钮逐页写不同品牌色、用占位符替代名称、点击后立即伪造队列成功。
正确做法：复用 Button/Input 和语义 token，保持可访问名称，显示 pending/error，
由既有 runtime 的权威状态决定最终呈现。

## 八维自检与可验证结果

每项检查都要有受影响的页面/状态、具体观察、必要修正与最终证据。
下表是项目的验收要求，不是对奖项官方评分规则的转述。

| 维度 | 必须检查并修正 | 证据与通过条件 |
| --- | --- | --- |
| 排版 | 中文、英文/ID、长配置、用户名的层级、行长、断行、对齐与字体回退；200% 文字放大后仍可读可操作。 | 默认及长文案的最终截图与文字边界检查；无裁切、重叠或装饰性强制换行导致的语义破碎。标题语义、可访问名称与阅读顺序正确。 |
| 留白 | 相邻元素按关系分组，入口台有明确边界；桌面观看区充分利用空间，固定 dock 下聊天填满剩余高度。 | 检查完整视口及内容填充态；没有误留网格列、悬空控件、无用途大空洞；队列、dock、composer 对齐满足 room contract。 |
| 视觉层级 | 每个当前任务有明确主动作，加入/创建、观看/管理、消息/设置主次一致；状态、错误不被次要装饰淹没。 | 匿名、已登录、入室等待、已入室及角色态的截图/操作路径；先看见任务，再找到状态与辅助操作。不能靠增大所有标题制造层级。 |
| 色彩 | 主题语义与文字/图标对比，包含 muted、占位文字、错误、焦点及真实背景叠加；状态不只依靠颜色。 | 普通有效文本目标 ≥4.5:1；大字（≥24px 或粗体 ≥18.66px）及必要控件/状态图形目标 ≥3:1。记录实际颜色组合；禁止以父层 opacity 弱化必要文字。装饰及非活动控件不冒充有效内容。 |
| 动效 | 普通与 reduced-motion 模式、首次进入与状态切换；动画期间也可操作，反馈不触发布局跳动。 | 分别验证正常动画和减弱动画；reduce 移除装饰 reveal/位移与弹跳，保留必要状态反馈。静态截图关闭动画不等于动效验证。 |
| 微交互 | 鼠标、键盘、触控的 focus/hover/press，名称、禁用、pending、成功、失败、重试；菜单关闭 inert，弹窗 Escape/背景点击与焦点返回。 | 用语义定位执行真实动作并断言最终状态；无 hover-only 操作、误触拖拽、重复提交或虚假成功。权限不足与断连不继续发命令。 |
| 响应式 | 窄屏、平板、桌面、横屏、短/高视口、安全区；长标题、满队列、聊天、展开设置、菜单和 cinema。 | 手机入口顺序保持 masthead → 邀请 → 入口 → 插画 → footer；部室堆叠、dock 固定/回流以 room contract 为准。无横向文字溢出、控件遮挡或不可达 composer。 |
| 原创性 | 图形、构图和细节能说明 Houkago 的共同观看场景；资产来源可追溯，新增视觉与现有教室语言连贯。 | 查看最终整页与关键局部并记录设计理由/素材来源；不靠套用通用落地页、模板拼贴或复制获奖作品。源码中存在原创 SVG 不单独证明完整体验达标。 |

样例：好的扩展将新观看状态融入既有投影舞台，保持动作与状态清楚；基础实现复用
主题与控件并覆盖各种状态；失败实现仅更换巨大标题、渐变和阴影，却未解决手机遮挡、
长文本裁切或加入/创建竞争。八项任一有明显问题，都需要继续修正。

## 验证、迭代与完成条件

1. 开始前读取本契约和受影响的 frontend runtime/spec，确认当前设计与交互不变量。
   正常 UI task 在批准的规划文档中明确构图、主次、状态和移动端覆盖，并将本文件显式加入
   implement/check context。明确授权的 no-task 工作直接读取，不为加载规范创建 task。
2. 通过真实组件路径实现，检查受影响的正常、loading、empty、error、disabled、
   pending、成功及权限态。未改变且无影响的页面不扩展成额外重设计范围。
3. 按 [validation](validation.md) 运行适用的桌面/手机 Playwright 和工程检查。
   入口使用现有 `entry-desktop/phone`；涉及身份连续性使用 `real-cookie/real-cookie-phone`；
   部室使用受影响功能的 desktop/phone 及适用的 `room-layout-*`。复用现有有效断言，
   新增测试只针对缺失的行为/布局风险，不写组件实现镜像或只检查 CSS 字符串的假验收。
4. 布局改变至少查看 320/375px 手机、768/812px 中间宽度、1280/1440px 桌面；
   涉及断点的布局还检查断点两侧，固定区域检查横屏与短/高视口。验证 200% 文字、
   长配置/无空格字符串及 normal/reduced-motion。不同宽度的机械截图不代替手机交互。
   先等待动画稳定再量几何；按 validation 使用 `animations: "disabled"` 保存静态诊断图，
   并单独验证动画行为。`overflow-x: clip` 不能作为文字未溢出的证据。
5. 查看最终整页及关键状态截图，按八项逐项自检；记录“问题 → 修改 → 复测结果”。
   正常 task 写入已有 validation 证据；no-task 使用 `/tmp` 临时证据与最终报告，
   不新增平行记录系统。截图无批准的确定性基线，不能自动更新 snapshot 后宣称通过。
6. 修正每个已发现的明显问题，再复测相关流程和桌面/手机状态，并在最后一次修改后
   对最终源码重做八项整体检查。主题或共享组件修改要复核首页与部室，避免逐页漂移。

“没有明显可提升之处”的完成条件：需求满足、适用检查通过、最终八项复核没有遗留的
可具体指出并在当前范围内改善的视觉或交互问题，且修正没有造成其他页面回退。
不得仅给自评分数、以“看起来不错”结案，或将可复现缺陷留给用户自行找出。
无法验证的必要项按 validation 记录为未验证，不能标为通过；范围外新需求另行说明，
不降低本次标准，也不擅自扩展。主观偏好按已有 human-review 分类处理，尊重已有
用户验收与提交授权；文档更新本身不要求再次视觉验收。
