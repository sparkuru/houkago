# Mainline Continuity

`.trellis/mainline.md` records direction/approval; normal Trellis parent/child
PRDs, designs, plans, checks and archives retain detailed evidence. Do not build
another scheduler, task schema or backlog.

## Sources and transitions

At task start and after interruptions, read mainline and source criteria.
Map acceptance to approved outcomes; resolve conflicts before changing scope.
Root `design.md` is human-authored context, not automatic authority to reopen
approved task decisions. Preserve source documents.

When importing missing requirements, retain repository-relative source/section,
scope/non-goals, acceptance, approval/draft status and unresolved conflicts.
Existing approval carries forward; proposed direction authorizes no work.
Do not substitute filenames, timestamps or current code for product approval.
With no declared initiative, report missing evidence instead of inventing one.

On authorized create/start, update that normal task's links/state/order. On an
approved requirement change, reconcile constraints, sources and affected work.
After checks, distinguish verified acceptance from implementation/limitations.
At archive, update paths, delivered scope, work/archive commits, remaining work
and next decision; preserve still-applicable history. Reruns merge evidence
without duplicate rows or erased user edits.

## Trellis Plus: Mainline Continuity

For relevant no-task status/continuation/next-work requests or after archive,
run a read-only Project Pulse: read mainline, active/archived evidence, git
state and validation; report initiative/completed evidence, exact dirty/blocker
conditions, one candidate only if uniquely ready, and next permitted action.
Do not trigger a Pulse for unrelated questions or assume archived `completed`
remains visible through the active-task resolver.

Default to `guided`: recommend and wait for scope selection. `paused` reports
state only. `serial` needs recorded initiative, ordered allowed tasks, readiness
and stop conditions; it authorizes only listed ready work and does not waive
planning, checks, review or commit/archive decisions. Stop for dirty overlaps,
missing dependencies, ambiguous choices, risk or scope changes.

Existing mainline preserves M6 planning-only approval and the independent
in-progress room-control child. Read current records rather than treating this
update as approval for M6 execution, legacy removal or deployment. Requirements
are already imported; no new scope is promoted by this reconciliation and
existing dirty mainline content remains untouched.

The main session owns task/phase choices, dispatch, commits, archive and mainline.
Workers receive a bounded authorized task and return changes, checks and open
decisions; they do not choose subsequent work or archive independently.
